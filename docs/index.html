Works in Telegram, Signal and WhatsApp. The transcript arrives in the same chat a few seconds later. It runs on your own server, so the audio stays there.

Use the messenger you already have

Each messenger is a plugin. Run one or all three, each with its own list of people allowed to use the bot. Anyone else is told their sender ID, so you can add them.

Telegram

Bot API · long polling

Create a bot with @BotFather and paste the token. No public URL or open port needed.

Handles voice messages, audio files and round video messages.

Signal

signal-cli-rest-api

Give the bot its own number, or link it to your account as a second device.

Linked to your account, you forward voice notes to Note to Self and the transcript appears right under them.

WhatsApp

WAHA · webhook

Links like WhatsApp Web. Use a second number, or your own account with Message yourself.

A second number is safer: WhatsApp doesn't officially allow unofficial clients.

Pick the engine per chat

Local models run on the CPU through ONNX Runtime. Switch between them in any chat with /engine and compare on your own messages.

Commands

Send these in any chat with the bot. Settings are remembered per chat.

/enginesList the engines and show which one this chat uses
/engine canarySwitch this chat to another engine
/lang deSet the spoken language for Canary; /lang auto resets it
/details onShow engine, language, audio length and processing time under each transcript

Self-host it in four commands

Needs Docker. The image is about 880 MB; the default model downloads on first start and takes about 0.8 GB of RAM while loaded.

~/repos
git clone git@github.com:then4p/tldl.git && cd tldl
cp config.example.yaml config.yaml   # engines, messengers, allowed senders
cp .env.example .env                 # your Telegram bot token
docker compose up -d
